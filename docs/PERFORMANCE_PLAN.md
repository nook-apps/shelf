# Производительность и ресурсы: дополнение к плану выпусков

Аудит 16 ноября 2026, база — `09b8764`. Существующий план: задачи
[#21–52](https://github.com/nook-apps/shelf/issues) и майлстоуны 0.5.1–0.7.0.
Ниже — распределение находок аудита, а не замена функционального плана.

## До 0.5.1: конкретные исправления без изменения интерфейса

- [x] **P1. Ошибка запуска picker:** единое завершение запроса при `finished` и
  `FailedToStart`, ровно один ответ/сброс счётчика, удаление процесса и временного файла,
  снятие регистрации D-Bus. Убрать блокирующий `waitForStarted`.
  Регрессия: три последовательных запуска с отсутствующим интерпретатором; после каждого
  приходит `idle`, дочерние ресурсы освобождены.
- [x] **P1. Ограниченные кэши миниатюр:** LRU для готовых и неподдерживаемых файлов,
  максимум по 4096 записей. Дисковый кэш не удалять. Проверка вытеснения и сохранения
  недавно использованных записей. Восстановление заказов tumbler после перезапуска — отдельно в #31.
- [x] **P2. Вывод архиватора:** хранить хвост до 8 КиБ, считать строки bsdtar по новым
  порциям, корректно обрабатывать разрывы строк между чтениями. Не пересчитывать весь
  журнал каждые 100 мс. Проверки границ порций, длинного вывода, ошибок и существующий
  цикл сжатия/распаковки/отмены.
- [x] Сборка и `ctest`: core, resources, i18n.
- [x] Проверка собранного приложения: навигация, вкладки, настройки и окно выбора файла.

Также реализованы #23 (новые ключи сортировки) и #24 (группировка). На 10 000 файлов
медиана открытия в локальном тесте с прогретым файловым кэшем: 131 мс с группировкой
и 128 мс без неё (разница 3 мс).
#25 — выпуск после проверки CI и сборки пакетов на GitHub.

## 0.6.0: сначала измерение, затем устранение задержек

1. **#26 — стенд измерений (первым).** Добавить к существующему сценарию: Ctrl+A и рамку
   на 1/10/50 тысячах файлов; 512 сохранённых видов; переключение вкладок; многократное
   открытие/закрытие папок с миниатюрами; быстрый просмотр на медленном носителе.
   Изолировать HOME/XDG, записать базу 0.5.1. Измерять медиану/p95 времени и рост RSS;
   ASan/LSan — отдельный прогон жизненного цикла объектов. Рост RSS сам по себе не считать утечкой.
2. **#27 — фоновое чтение каталогов.** Убрать ожидания `stopSearch/stopSniff`:
   отмена по поколению без блокировки UI, без обращения к уничтоженному `DirModel`.
   Подсчёт содержимого подпапок ленивый. Проверки быстрого перехода и закрытия вкладки
   во время поиска/MIME/медленного I/O. Не удалять `waitForFinished` без переработки владения.
3. **#28 — точечные обновления.** Ограничить `dataChanged` реально изменёнными строками
   и ролями. Добавить индекс путь → строка и убрать O(N²) в `sizeOf`, `prune`, `selectPaths`;
   не вызывать `sizeOf(sel)` дважды для одной строки состояния. Проверять индекс после
   сортировки, вставок, удаления, поиска и reset.
4. **#29 — ключи сортировки.** Сохранить существующую задачу; сравнить выигрыш по #26.
   Отдельно применить ключ и направление одним обновлением модели: сейчас восстановление
   вида может пересортировать её дважды.
5. **Дополнение к #22: кэш FolderViews (P1 для 0.6.0).** Состояние в памяти с наблюдением
   за файлом, отложенная объединённая запись, сохранение изменений нескольких процессов.
   Не проверять все 512 путей при каждом get; очистка отсутствующих папок отдельно.
   Сохранить семантику «открытие не закрепляет вид» и режим picker только для чтения.
6. **#31 — миниатюры и делегаты.** Адресные уведомления о готовности; файловые проверки
   вне UI; заявки видимым элементам. При потере сервиса очищать зависшие ожидания,
   при возвращении заново получать возможности/размеры и повторять нужные заявки.
   Проверки отсутствия/перезапуска tumbler после принятия заказа. Упрощать слои/эффекты
   только после профиля и сравнения картинки.
7. **Quick Look: просмотр документов (P1 для 0.6.0).** Пользователь сообщил, что
   предварительный просмотр не работает со многими документами. Собрать воспроизводимые
   примеры и матрицу распространённых форматов (в том числе PDF, ODT, DOCX, XLSX, PPTX,
   RTF); для каждого различать отсутствие поддержки, ошибку определения типа, сбой
   миниатюр и зависание загрузки. По результатам определить и реализовать полезный
   просмотр поддерживаемых форматов, а для остальных показывать понятное состояние.
   Проверить открытие нескольких документов подряд и работу без сервиса миниатюр.
8. **Ограничение задач Quick Look (P1, отдельная подзадача 0.6.0).** Обрабатывать актуальный
   запрос и не копить устаревшие чтения в общем пуле. Учитывать, что системное чтение может
   блокироваться: ограничить число одновременно выполняющихся задач, проверить выход из
   приложения и закрытие просмотра. Результат старого поколения не показывать.
9. **#30 — запуск и системные интеграции.** Замерить синхронные вызовы портала темы,
   hyprctl, первое чтение обоев, Apps::scan/xdg-mime и опрос томов. Переносить подтверждённые
   задержки в фон. Типизация QML полезна, но не включать C++ AOT автоматически: текущая
   bytecode-only сборка намеренно избегает привязки пакета к private ABI конкретного Qt.
10. **Подзадача #44, перенесённая по приоритету в 0.6.0:** фоновые свойства папки с отменой
   и постепенным результатом. Лимит 100000 объектов не ограничивает время I/O.
   Новые функции свойств (права, суммы) остаются в 0.6.2.

## 0.6.2: вместе с переработкой файловых операций

- **#45 — очередь операций:** пересмотреть отмену и завершение приложения во время
  удаления/очистки временной распаковки. Сейчас `removeRecursively` не прерывается флагом,
  а `discardExtracted` удаляет дерево синхронно. Ограничить частоту progress для удаления
  и undo (сейчас возможен queued-вызов на каждый элемент/шаг).
- Проверить память undo на больших слияниях: лимит 50 операций не ограничивает число
  шагов внутри одной. Ввести бюджет только если измерения покажут значимую нагрузку;
  не ухудшать возможность восстановления файлов ради небольшой экономии памяти.
- **#44:** права, контрольные суммы и остальные функции по существующему плану.

## Пока исключено из самостоятельных задач

- Переписывание `afterFrame` только из-за порога 8 мс: оставить до воспроизводимого сбоя
  или плохих кадров на конкретной частоте дисплея; диагностика входит в #26/#31.
- Замена прогресса распаковки через `/proc`: сейчас это приблизительный индикатор,
  а не источник целостности данных. Менять при подтверждённой неправильной работе.
- Полный PNG-парсер вместо чтения начала файла: сначала нужен образец миниатюры,
  которую текущий разбор ошибочно отвергает. Не усложнять без сценария.
- Выгрузка всех фоновых вкладок, глобальное переписывание QML или графических эффектов:
  возможны регрессии состояния/анимаций; решение только по профилю #26/#31.
- Остаточный переводчик на завершении процесса: низкий приоритет, не растёт при
  переключении языка (предыдущий удаляется). Проверить в рамках LSan, не блокировать релиз.
